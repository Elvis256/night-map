# NightMap

East Africa's social companionship platform: seekers discover verified companions on a city map, connect and chat, request bookings, rate meetups, and join live streams and radio lounges. Companions manage a listing (rate, menu, availability, tonight's deals), receive requests, and go live.

## Run & Operate

- `pnpm run dev:api` — build + run the API server (reads `PORT` and `DATABASE_URL`; falls back to the root `.env` locally, port 5000)
- `pnpm run dev:mobile` — Expo dev server on port 8081 (local only; Replit uses the artifact's own `dev` script)
- `pnpm run db:push` — push Drizzle schema changes (dev only, needs `DATABASE_URL`)
- `pnpm run seed` — seed demo companions, seekers, lounges, bookings and reviews (idempotent). All seeded accounts use PIN `1234`; companions are `+256700000001`…`010`, seekers `+256700000101`…`104`, admin `+256700000999`.
- `pnpm run codegen` — regenerate react-query hooks (`lib/api-client-react`) and zod validators (`lib/api-zod`) from `lib/api-spec/openapi.yaml`; also rewrites `lib/api-zod/src/index.ts`
- `pnpm run typecheck` — full typecheck (libs first via `tsc --build`, then artifacts)
- Required env: `DATABASE_URL` (Postgres), `PORT`. Optional: `UPLOADS_DIR` (defaults to `artifacts/api-server/uploads`), `HIGH_END_RATE_UGX`, `EXPO_ACCESS_TOKEN`; on the mobile side `EXPO_PUBLIC_API_URL` to point at a specific API host.

## Stack

- pnpm workspaces (`packageManager: pnpm@10.20.0`), Node.js 22/24, TypeScript 5.9
- API: Express 5, bearer-token sessions, scrypt-hashed 4-digit PINs
- DB: PostgreSQL + Drizzle ORM (`lib/db/src/schema/*`)
- Validation: Zod (`zod/v4`) generated by Orval from the OpenAPI spec
- Mobile: Expo 54 / expo-router, TanStack Query, generated hooks from `@workspace/api-client-react`
- Build: esbuild (CJS bundle) for the API

## Where things live

- `lib/api-spec/openapi.yaml` — the API contract (source of truth for hooks + validators)
- `lib/db/src/schema/` — tables grouped by domain: `users` (users, companion_profiles, sessions, photos, verification_requests), `social` (swipes, saved, profile_views, stories), `messaging` (connections, messages), `bookings` (bookings, reviews), `engagement` (notifications, points_ledger, referrals), `safety` (trusted_contacts, safety_events, sms_outbox), `wallet` (wallet_ledger), `media` (streams, lounges, outage_reports)
- `artifacts/api-server/src/routes/` — one router per domain; `src/lib/` holds auth, serializers, companion card building, notifications/points, storage, weather
- `artifacts/mobile/context/AppContext.tsx` — the app state layer: auth session, companions/stories/deals/connections/bookings queries, mutations with optimistic updates, filters
- `artifacts/mobile/lib/api.ts` — API base URL resolution, token getter, `errorMessage()`, asset URLs
- `scripts/src/seed.ts` — dev seed

## Architecture decisions

- Auth is phone + 4-digit PIN (product decision). PINs are scrypt-hashed; 5 failed attempts lock the account for 15 minutes; sessions are random bearer tokens valid 90 days, stored in `sessions`.
- Companion cards are computed server-side (`src/lib/companions.ts`): rating/review count from `reviews`, hot streak = 2+ completed meetups in 7 days, new in town = joined < 14 days, spotlight = `featured_until` in the future, deal = `deal_discount` with a live `deal_expires_at`, trust score from verification + meetups + rating. Ghost-mode and hide-from-search users are excluded.
- Bookings have a real lifecycle: pending → upcoming (companion accepts) → active (either side starts) → completed; or declined/cancelled. Completing increments `completed_meetups`, awards +100 points to both sides and records an informational `earning` ledger entry (status pending: payments are off-platform).
- No payment provider: wallet shows balances/earnings from the ledger with `paymentsEnabled: false`; top-ups, payouts, tips and package checkout stay disabled until a provider approves the business model.
- Realtime is polling (chat 3s, inbox 8s, unread 10s). Streams and lounges are real at the data level (presence, comments, hearts, hosting); audio/video transport is not connected.
- Safety: panic/check-in create `safety_events`, queue SMS rows in `sms_outbox` for trusted contacts (no SMS gateway wired yet) and notify admins in-app.
- Verification uploads are stored privately under `uploads/private`; admins (`users.is_admin`) review via `/api/admin/verifications`.
- Entitlements without checkout: `lib/billing.ts` defines the packages; a companion with a rate ≥ `HIGH_END_RATE_UGX` (default 150,000) is in the High-End collection and appears `locked` to seekers without High-End Access (connect/book return 403 `high_end_locked`). Free seekers get 3 super requests per day (`super_limit`), VIP unlimited. Users can register interest (`POST /subscriptions` → status `requested`); admins activate with `POST /admin/subscriptions` (Featured also sets `featured_until`). `checkoutEnabled` stays false.
- Push notifications: devices register Expo push tokens (`POST /me/push-token`); every `notify()` call also sends an Expo push (needs an EAS `projectId` in app config on the client; set `EXPO_ACCESS_TOKEN` on the server for enhanced security). Dead tokens are pruned on `DeviceNotRegistered`.
- Companion onboarding: new companions land in `app/companion-setup.tsx` (photo, bio, menu/vibes, rate, availability); the profile tab nudges until a photo and menu exist.

## Product

- Map + Discover (swipe, categories, stories), companion profiles with reviews, connection requests (standard/super), chat with voice-note placeholders and system lines for booking events
- Bookings for both sides, chemistry-score reviews, loyalty points and tiers, referrals (+200 pts), notifications
- Companion onboarding wizard, listing management, photo upload, stories, tonight's deals, go live
- Packages with entitlements (High-End collection gating, super-request limits) and admin grants; push notifications
- Safety hub (trusted contacts, panic, check-in, incident reports), who-viewed-me, weather (Open-Meteo) and community outage reports on the map
- Radio lounges and live streams (presence/chat), wallet (informational), packages preview

## User preferences

- Maximise earnings and user growth; free basic listing and browsing; High-End Access UGX 20k/month and Featured placement UGX 100k/week are the planned paid tiers.
- Never enable real checkout or imply a payment succeeded until a payment provider has approved NightMap's services in writing.

## Gotchas

- Run `pnpm run codegen` after editing `openapi.yaml`; the server imports zod schemas by operationId (`CreateBookingBody`, `ListCompanionsQueryParams`, …).
- Generated hooks require an explicit `queryKey` in `query` options (`useGetScore({ query: { queryKey: getGetScoreQueryKey() } })`).
- `pnpm run typecheck:libs` (`tsc --build`) must run before the mobile typecheck sees new lib exports (declarations are emitted to `lib/*/dist`).
- Under `CI=true` pnpm needs `--no-frozen-lockfile` to add dependencies.
- Expo typed routes (`.expo/types/router.d.ts`) only regenerate when the dev server starts; after adding a route run `expo start` once (or the typecheck will reject the new path).
- The mockup-sandbox artifact has a pre-existing `@types/react` duplicate-type error unrelated to the app.
